# 情欲场景数据包（18+）

**默认不参与构建。** 只有 `npm run build:adult` 才会把这里的内容打进包。

## 为什么单独一个目录

D-029：明确的情欲场面由 YIDI 本人写，不是 ChatGPT 也不是 Claude。
工程上把它隔离成一个可插拔的数据包，好处有三条：

1. 同一份代码出两个版本。全年龄版在屏风前停住，18+ 版接上后面。发哪一版由 YIDI 定。
2. 这些文字不进默认产物，也就不会因为一次误发链接而流出去。
3. 写作节奏和主线脱钩。主线可以先跑通，这几场慢慢写。

## 放什么

一场一个 JSON，格式与普通场景完全相同（`docs/story-schema.md` 第二部分），
放在 `chapters/` 下按章分目录：

```
src/data/adult/
├── README.md
└── chapters/
    └── ch02/
        └── ch02_s12a_yuanye.json
```

每条恋爱线 1 到 2 场，共 4 到 8 场，每场 300 到 600 字。

## 怎么接进主线

全年龄版的那一场在屏风前收尾，出口指向下一场。
18+ 版里，同一个场景 id 的文件放在这里会**覆盖**主线里的同名场景
（加载顺序：先主线，后 adult，后者胜）。这样接与不接都不用改主线的去向。

也可以另起一个 id，由主线场景的某个选项 `goto` 过来——那个选项在
全年龄版里指向屏风前的收尾场，在 18+ 版里被这里的同名文件覆盖。

## 两条硬规则

- **同意必须在文本里可见。**「她可以拒绝」这条原则在这些场景里最严（D-029）。
- 色板、立绘、UI 一律照旧。这里只是文本，不新增视觉资产。

## 构建

```bash
npm run build           # 全年龄版，这个目录整个不进包
npm run build:adult     # 18+ 版
```

不是靠 `if` 跳过：`vite.config.ts` 里的 `virtual:adult-scenes` 插件在关掉时
直接返回空数组，这些文件从头到尾没有被 import 过，产物里连字节都没有。
