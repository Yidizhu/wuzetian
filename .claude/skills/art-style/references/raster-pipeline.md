## 一、一张图从生成到进游戏

```
Codex 生成 ──► assets/portraits/<asset>_v<N>.png          原件落盘（一版一个文件，不覆盖）
                     │
                     ├─ npm run art:post -- portrait <套> --v N --eye <行>    机器：抠底、量、报警，出检查图
                     ├─ npm run art:post -- silhouette <原件> <已验收的…>      门槛 1：120px 剪影
                     ├─ 人看：SKILL.md 七道门槛 + 两条否决
                     │
                     ├─ 不过 ──► ledger 记哪一道没过，提示词改哪句 ──► Codex 出 v<N+1>
                     └─ 过   ──► ledger 记「过」
                                  └─► public/char/full/<file>.webp  +  public/char/knee/<file>.webp
                                        └─► CC1 接进引擎（新旧并存）
```

## 三、命名

**原件**：`<who>_<身份>_<色>_<表情>_v<N>.png`——照 Codex 第一张实测图已经在用的写法定，不另起一套。
- 例：`wuze_cairen_qing_default_v2.png`、`shenheng_siji_shenlv_default_v1.png`、`peizhaoye_nvjiang_yanzhifei_default_v1.png`
- 主角只有两套（D-105）：青 `wuze_cairen_qing_default`，登基之后绯 `wuze_tianzi_fei_default`
- 表情这一轮只有 `default`（D-095：每套先一个中性表情）
- 版本号只增不改；**不许覆盖旧版**——对照上一版是验收的一部分（v1 → v2 的七条就是这么对出来的）

**引擎名**：`<who>_<expr>[_<后缀>]`，和现在 SVG 的名字一样，好让引擎拿不到变体时照旧退回 `<who>_<expr>`（`src/char/sprite-rules.ts` 的规矩）。
- 主角：青是底 `wuze_default`；绯 `wuze_default_fei`（`enthroned` 之后，D-105）
- 李令仪：郁金是底 `liqinghe_default`；礼衣紫 `liqinghe_default_zi`
- 柳承欢：`liuchenghuan_default_bare`

两套名字的对照、每套的身高与底色，**只写在 `src/char/portraits.ts` 一处**（D-098）。
哪个 flag 选哪个后缀是 CC1 的事（D-091），这张表只管「有哪些图、叫什么」。

**背景**：原件 `assets/scenes/<场景>_<状态>_v<N>.png`，引擎名 `public/scene/<场景>_<状态>.webp`。
状态是「地点·色板·布置」的组合（CC1 数过：现在 16 种，C15 之后 17 种），**只画日景**，夜场引擎套冷暗滤镜（D-107）。清单以 CC1 的背景表为准，别先生成。

## 四、后处理：`npm run art:post`

零依赖，像素活在无头 Chrome 的 canvas 里做（和 `art:loop`、`art:screens` 同一个驱动），webp 也是 Chrome 编码的。

### 立绘 `portrait <引擎名> [--v N] [--eye 行]`

1. **抠底**。背景色取画面外圈两像素的中位数；离背景色（逐通道最大差）≤ 24 的、从外圈连通过来的算背景。
   被身体围住的底色空洞（帔帛和身体之间）大于 800 像素的也挖掉；**小的（≥120 像素）只要八成以上像素离底色 ≤ 10 也挖**（E13：双鬟望仙髻的环心只有几百像素，按 800 挖不掉，B17 手机截图里头顶留了两个白点。白中单领口、衣服高光有明暗，过不了这一条，主角 v3、裴照夜 v1 实测没误伤）。紧挨背景的两圈像素按离背景色的远近给半透明，并把混进来的背景色减掉——**不减的话，放到墨色的场景前面，人会镶一圈白边**。
2. **量**，并在报警里说出来：背景是不是纯色（外圈 95% 以上接近底色）、头顶／脚／侧边出没出画、发髻顶离上边够不够（2% 以上）、要不要放大（放大超过 5% 就糊，多半说明人在原件里画小了、脸也不够大）。
   **规定中灰底的那几套交了白底图，也报。**
   另报「头顶透光」：眼睛行以上挖成透明的孔各多宽多高（E14，门槛 1a「环里透光」用它）。
   另报「身上的空洞」（眼睛行以下挖掉的，逐个在品红底上认）和「险边」（人身上离底色只差 25–48 的像素占比，超过 3% 报警）——E17，给中灰底的浅色衣服用。
3. **同一把尺子**（`src/char/portraits.ts` 的 `CANVAS`）：画布 1024×1536，**脚底落在第 1500 行**，身高按 `height` 缩——主角 1280 像素，裴照夜 1.1 倍，阿荻 0.94 倍。
   横向按「眼睛到脚底之间的不透明度重心」居中，不按外框居中：帔帛、刀、挽起的袖子会把外框拉偏。
4. **身高用眼睛算，不用外框算。** 外框的顶是发髻、冠、幞头脚的顶——按外框缩，单刀半翻髻和何太后的冠会把人缩矮一截。
   验收时从检查图上读出**眼睛那一行**（原件的像素行），`--eye` 传进去：身高 =（脚底 − 眼睛）÷ 0.936。
   没给 `--eye` 就退回外框，并报警。这一个数记进 ledger，下次重跑不用再读。
5. **出两张**：全身 `public/char/full/<file>.webp`（1024×1536），膝上 `public/char/knee/<file>.webp`（第 0 到 1080 行，1024×1080）。质量 0.82。
6. **检查图** `Claude outputs/art-post/<file>-check.png`，五格：
   原件 + 每八分之一画面高一道线（**头从颅顶到下巴要跨满一格**，否决条「脸糊了」就看这个）｜纸底｜墨底｜品红底（**白边在品红上最显眼**）｜膝上裁切。
   中间三格上画着脚底线、膝上裁切线、按身高推出来的眼睛线。

### 膝上裁切：为什么是固定的一行，不按每个人算

D-095 第 2 条：**一次生成，两种裁切**，绝不为了脸大另生成一张半身（两次生成必然两张脸）。

裁切行固定在同一把尺子的**第 1080 行**，对十三套一样：
- 裴照夜（1.1）身高 1408 像素，膝盖约在第 1099 行——裁在膝盖上面一点
- 阿荻（0.94）膝盖约在第 1157 行——裁在她膝盖上面一截
- **按每个人自己的外框去裁「膝上」，对话里十一个人就又一样高了。** 身材差别是 D-095 第 3 条的硬要求，裁切不能把它抹掉

**手机竖屏上膝上图只放大约 1.12 倍，不是 1.42 倍**（E13，`src/styles/raster.css`）：撑满槽位的 1.42 倍让一个人的图比整个屏幕还宽，两个人叠在中间、手臂出了屏幕边。竖屏上两个人并排，每人最多半屏宽，放大只剩这么多；要看脸大靠宽屏。截图对照 `Claude outputs/art-post/e13-knee-phone-before.png` / `-after.png`。

什么时候用哪一种（D-108，引擎按规则选，不加字段）：**这一格有选项就用全身，其余用膝上**——要做决定的时候镜头退开，看得见她整个人。膝上图里头约在上三成，手机上脸够大。

### 柳承欢的 `_bare`：修，不生成

她的朱砂点是腕上一根朱绳（D-038）。归还之后那一套**从验收过的 `liuchenghuan_default` 上把朱绳修掉**，不重新生成——重新生成就是另一张脸、另一个人，而这个设定的意思恰恰是「她还是她，只是身上借来的东西还了」。
修图这一步不在 `art:post` 里（它不会画东西），修完的文件记成 `liuchenghuan_gongren_huiqing_default_bare_v1.png`，再走一遍 `portrait liuchenghuan_default_bare`。

### 背景 `scene <key> [--v N]`

长边缩到 1920，**不放大**；长边不到 1536、竖构图、比例离 16:9 太远都报警。
检查图画出**手机竖屏（390×844）铺满时看得见的三条**——左、中、右，也就是整图轻推平移的起止范围——和底部 22% 的对话框。

### 排队 `lineup`、剪影 `silhouette <图…>`

- `lineup`：`public/char/full/` 里已出的全身图脚底对齐排一排，画出脚底线、膝上裁切线、主角头顶线（门槛 5）
- `silhouette`：抠底涂黑、缩到 120px 高并排，上排实际大小、下排同一张像素放大三倍给人看轮廓（门槛 1）。可以混排生成原件、`public` 的 webp、旧 SVG

以上都能加 `--out <目录>` 把产物写到别处试跑，免得测试图进了 `public/`。

### 这一轮怎么验的

没有生成新图（E11：这一轮不生图）。用了两种输入：
1. **旧 SVG 当替身**：主角、裴照夜、阿荻、许静和四张 SVG 各自撑满画面、加噪声底，模拟「生成图人人顶天立地」。排队图里身高顺序恢复成裴 > 许 ≈ 主角 > 阿荻；帔帛与身体之间的底色空洞挖对了；许静和中灰底／白底两版都跑过。
2. **Codex 的真图 `wuze_cairen_qing_default_v2.png`**：抠得干净，墨底与品红底上看不出白边，裙摆与手臂之间的空洞挖对了；报了一条真问题——发髻顶离上边 6 像素。

**替身测不出的**：真正的月白、缃色衣服在白底上会不会被吃边——替身的浅色是平涂，边缘和白底差得开。中灰底的规定是按原理定的，第一张许静和回来要专门看墨底那一格。

**E18 第一张真样本回来了：中灰底对月白不成立。** 许静和 v1 在中灰底上抠坏——右半边袍子和道帔的暗面落到了中灰上，被啃出锯齿洞。
阿荻 v1（本色麻）在同一种底上抠得干净。所以浅色、灰色系衣服（缃、月白、灰青）改用**绿幕**：挑一种这个人身上完全没有的颜色（`portraits.ts` 的 `bg`）。
**底色规格（D-149，E20 写死）**：

| 底 | 给谁 | 现在是哪几套 |
|---|---|---|
| 白 `#FEFEFE` | 默认：主色够深、够有颜色 | 主角青与绯、沈衡、裴照夜、李令仪两套、宋蕙贞、何太后、唐简 |
| 中灰 `#808080` | 暖的中间调，离中灰够远 | 阿荻（本色麻） |
| 绿幕 `#00B140` | 浅色、灰色系，**并且身上没有绿** | 许静和（月白）、温荞（缃）、柳承欢（灰青） |

**穿绿的人一律不许绿底。** `art:post` 的 `bgClash`：清单里配错直接挡住所有命令；原件底色和主色逐通道最多差不到 48、或者两者同色相（差 < 40°）→ 那一张不出图。
两条都实跑触发过（E20：沈衡临时改绿底 → 全部命令拒跑；唐简拿绿幕原件跑 → 不出图）。**它只看主色**：暗面落到底色上查不出，墨底那一格照看。

「险边」那个数（E17 定过 3% 报警线）两张真样本证明分不开好坏（阿荻 22% 干净、许静和 12.8% 坏），降为诊断参考（D-129）；判抠没抠坏，看检查图的墨底和品红底。
**绿幕要新看一件事**：绿光反到浅色衣服上，最外两圈之内的发绿抠底减不掉——品红底那一格看衣服边有没有一圈绿。第一张绿幕回来（许静和 v2）专门看。
**E22 实跑结果与修法**：许静和 v2、温荞 v1、柳承欢 v1 三张绿幕，外轮廓干净，但**臂弯、帔帛和身体之间被围住的小缝里留着绿**——那些缝小于 800 像素、又带着抗锯齿的过渡色，按「纯底色的洞」判不出来。
`cutout` 加了绿幕模式（`bg: "green"` 自动开）：① 「绿明显多过红蓝 50 以上」的像素一律算底；② 被围住的洞 ≥ 30 像素就挖；③ 抠完做一遍去溢色——每个留下的像素绿不许超过红蓝里大的那个。白底、灰底不走这条，行为不变。

## 五、整图轻推（Ken Burns）归谁

> **E12 更新**：B17 里 Cowork 把「背景表 + CSS 版加整图层 + 推近」排给了 CC1（C 线，不等人）。下面是 E11 的提案，留作对照；
