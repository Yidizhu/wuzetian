## 一、关系词（D-154）

### 原来的漏洞比指挥日志说的还多一层

章末结算页原来已经在名字旁写了 `识／契／盟`，是按好感数算的。**这三档的下限正好是 4、8、14，也就是专属闲场的门槛。** 玩家看见「识」变成「契」，就知道自己刚跨过一道门。这正是 D-154 说的「倒推门槛」，而且已经上线了。

### 现在怎么算

不看好感数，看**发生过的事**：这个人的专属闲场，你真正走进去过哪一档，词就是哪一档。

| 词 | 条件 |
|---|---|
| （不显示） | 没来往过 |
| 有来往 | 好感大于 0 |
| 常来常往 | 进过她第一档专属闲场 |
| 相知 | 进过第二档 |
| 心照 | 进过第三档 |

- **好感跨过门槛、那场戏还没演**：词不变。词只在那场戏演完之后才变，而那场戏玩家已经亲眼看见了，所以不泄露任何东西。
- **好感后来掉下去**：词不退。走过的事不会被抹掉。
- **专属闲场不写死场次**：凡是进入条件里有 `affinity.<人> ≥ x` 的场，就算这个人的一档。按现在的数据推出来，四个人各三档，正是 ch01 13–16、ch02 15–18、ch03 17–20。剧本加一场或换一场，这里自动跟着变。
- **排序**：按词从深到浅排，同一档里按名字表的顺序，不让名次暴露差了几分。
- **措辞**：四个词在 `src/engine/relation.ts` 的 `RELATION_WORDS`，**措辞归剧本，ChatGPT 要换词只改这一处**。没用「生疏」，因为没来往的人本来就不上名单。

### 「这一章，你和某某走得最近」

只比**这一章**谁的好感涨得最多，不露总数：
- **没人涨**：不写这一句。
- **并列第一**：也不写。并列时点名任何一个，都是替玩家做了选择。
- **读档读在一章中间**：从读档那一刻开始算。
