## 二、这一轮真正找到的东西

R-017 说对了，而且比它列的八条更深一层。**整屏截图第一遍跑出来，问题不在哪一场，在做法。**

**立绘一律画到竖屏七成高，和场景用的不是同一台相机。** 于是：

- 景被整个挡在人腿后面，只剩几件道具从裙摆里戳出来；
- 女冠观的殿读成两个人腰边的一张**桌子**，含元殿读成两个巨人脚下的**沙盘**；
- 为了给「没有人的画面」压下沿，我每一场都放了一件近物（瓮、香炉、曲栏）——人一站上去，这些东西比人近，
  却被画在了人身后，**深度是反的**。

**R-017 第 3 条「人是浮着的」，整屏闭环量出了原因**：人站的位置写死在机位到看点的四成五，
那个位置的地面，大多数场景在对话框**下面**（地线 3%、−7%）。立绘被下限抬到 21%，**比真地面高出一截**。
百分比、面数、毫秒一条都量不出这件事——六轮全过闸门，是因为闸门量的是场景那一层。

所以改的是做法，不是一张一张地修：

1. **人和景用同一台相机量。** 渲染器在人站的地方投一个 1.62 米的人，立绘就画那么高，写进 CC1 留的 `--stage-person`。
   算出来太小的夹到 0.62（再小手机上认不出是谁），报告里标「夹住了」。
2. **人站在地露出来的地方。** 从四成五往里走，直到脚下那块地露出对话框为止。人站远了，按同一处算身高，自然就小——地线和身高一起对上。
3. **脚下一片墨影**（R-017 ③）。影子走 `--c-char-*`，金碧场景里也是墨：影子是人的，不是场景的。
4. **竖屏里人心定在屏宽 28% 和 72%。** CC1 那条竖屏规则把格子左右边钉在 −24% / −26%，人一收小就半个滑出屏幕。
5. **近处的东西要么挪到人身后，要么抬到人头以上**：御花园曲栏挪到人身后；掖庭门楣、女冠观和诗社的檐口抬高，离开人头那条线。
6. **俯视的机位放不下站着的人。** 含元殿原来 11 米高大俯视，站位上一个真人只占画面 6%。
   改成广场上人眼高、顺着龙尾道仰看殿，人收到 0.5。「人极小、殿压人」的意思没丢，而且现在是仰看。

这六条都写进了 `art-style/references/scene.md`「人站进来：整屏才是验收对象」。

**最该记住的一个数**：除了含元殿，每一场都「夹住了」——人按相机只该占画面 16%～25%，实际画到 38%。
**立绘仍然比它站的空间大一倍多。** 场景的机位是 E1 到 E6 为「只有景」定的，要一次看全一座殿；
人站进来之后该做的是逐场**把机位推近**，而不是再缩人（再缩手机上就认不出是谁）。含元殿这一轮先推了，是示范。
这件事和 P2 换 3D 人物是同一件事的两半：3D 人物天然和场景同一台相机，到那时这个「夹」就没有了。

**默认渲染器切不切（R-017 的顺序）**：我这边从「三章大半不成立」改到「八组成立、一组勉强」。掖庭那组我建议下一轮先改，但它不挡切换——要不要切是 Cowork 的判断。

## 五、整屏闭环怎么用

```bash
npm run art:screens                       # 三章每一场，约五分钟
npm run art:screens -- --chapter 2
npm run art:screens -- ch01_s01_zhaoyang
```

量四样**能量的**：脚离对话框顶边多少、立绘出屏多少、立绘透明度、留白成片。另外从渲染器读出「这台相机下真人该多高、地线原本在哪」，夹住了就标出来。
**「同一个空间？穿帮？框压住了什么」三栏机器不填**（D-071），留给看图的人。

`tools/art-loop.ts`（场景那一层）和 `tools/art-screens.ts`（整屏）共用 `tools/cdp.ts`：无头 Chrome 的驱动和一个 PNG 解码器，零新依赖。

场景那一层同时重跑了 21 个状态，**21/21 过**；昭阳殿去掉一对柱子后面数 1032 → 856，含元殿改机位后留白 76% → 70%。
「无字碑 · 结局卡」那一条补上了布置「印」——CC1 按 D-067 改成默认无印之后，这一条量的其实是无印的碑。
