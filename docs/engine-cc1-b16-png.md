# 立绘与场景换 PNG：要动哪些地方（B16 第 6 条，D-095）

2026-09-14 · CC1

## 结论

| 问题 | 答案 |
|---|---|
| 1 立绘从内联 SVG 换成图片，改动面多大 | **不大，集中在一处查图 + 一段 CSS。** 真正要换思路的只有两件：朱砂亮起（`.accent` 变色）在 PNG 上做不到，脚的位置要靠出图规格或每张图的元数据 |
| 2 场景整图 + 缓慢推近，在现有渲染器里是加法还是重写 | **加法。** `SceneRenderer` 接口一个方法都不用改。建议在 CSS 版里加一层「整图」，有图的场景走整图，没图的照旧画渐变 |
| 3 新旧并存 | **按「每张图一个键、找不到就退回」做，已经有现成的路**：B16 刚写的 `spriteCandidates` 就是「一串候选、第一张存在的就用」。PNG 只是排在最前面的候选 |

**有一件事要 Cowork 先知道：PNG 背景走的是 CSS 那条渲染器，不是 3D 那条。** 3D 舞台画的是几何体，一张整图放进去没有意义。D-095 定下之后，`DEFAULT_RENDERER` 要不要切成 3D（D-086）这个问题的分量变了：玩家最终看到的画面在 CSS 这条路上。3D 那条要不要继续投入，需要重新定。

## 一、立绘：SVG → 图片

### 现在的样子

- `src/main.ts:56` 在构建期把 `src/char/*.svg` 当文本打进主包（37 张，272 KB）。
- `CharacterLayer.show` 把 SVG 文本塞进 `innerHTML`。内联是故意的：墨色和朱砂点吃页面的 CSS 变量，金碧场景里朱砂自动变泥金。

### 要动的地方

| # | 位置 | 要做什么 | 大小 |
|---|---|---|---|
| 1 | `src/main.ts` 立绘清单 | 再加一个 glob 收 PNG／WebP，用 `?url` 取地址，**不打进主包**。清单变成「键 → SVG 文本或图片地址」 | 小 |
| 2 | `src/ui/CharacterLayer.ts` 的 `show` | 图片键就建 `<img>`：先 `decode()` 再换上，不闪白；SVG 键照旧 | 小 |
| 3 | `src/engine/identity.ts` 的 `spriteCandidates` | 候选链最前面加 PNG 键。**PNG 只有一个中性表情**，所以一个人一旦有 PNG，三种表情都用这张，不回到 SVG 的表情图——同一场里风格来回跳比表情不变更糟 | 小 |
| 4 | `src/styles/app.css` 的 `.cast__slot svg` | 选择器扩成 `svg, img`（呼吸、层级、说话时快一点），加 `object-fit: contain` 和 `object-position: bottom` | 小 |
| 5 | **脚的位置** | 现在的 CSS 假定脚在画布 93% 高度处（`bottom: … - 5.3%`）。AI 出图脚在哪不固定，两条路：**出图规格里规定「1024×1536、脚底在 93%」，入库时自动补边对齐**；或者每张图带一个 `footY`。**建议前者**，CSS 一个数不改 | 规格的事 |
| 6 | **朱砂亮起**（`cast.flare`，`.accent` 变色） | PNG 里没有可以单独变色的朱砂点。要换一种做法：叠一个小元素、按每张图记下的坐标亮一下，或者整个人一次很淡的暖光。**这是 D-010 的表达，要 CC3 和 Cowork 定** | 设计待定 |
| 7 | 膝上裁切（D-095 第 2 条：对话用膝上、登场用全身） | 同一张图两种框法，是 CSS 加一个状态：槽位比例、`object-position`、脚线不再对地。**哪几场用全身要有来源**，现在剧本里没有这个字段 | 中，要定来源 |
| 8 | 李令仪两套（D-092，礼衣紫／日常郁金） | 引擎要知道「这一场是正式场合」。剧本里没有，要加一个场景字段，或一张场次表，和 D-076 的人上台表一样 | 小，要定来源 |
| 9 | `src/scene/TiHua.ts` | 题画把 SVG 画到画布上。PNG 更简单，直接 `drawImage`。**题画现在没接进游戏**，可以最后做 | 小 |
| 10 | 工具 | 见表下五处 | 小到中 |

工具那一格的五处：

- **`tools/sprite-check.ts`**：只查 SVG。PNG 要另写：透明边有没有白边，D-095 的脸占画面高 1/8 以上、脚线在不在 93%。
- **`tools/smoke-chapter.ts`** 第三条不变式：按 `.svg` 查换图文件在不在，要认 PNG。
- **`tools/screen-shot.ts`**：量的是 `svg` 的框，要量 `img`。
- **`tools/check-bundle.ts`**：加一条，PNG 被以 base64 打进 JS 就报错。
- **`opening-preview.ts`、`tripo-ref.ts`**：开发页，留在 SVG 不动。

**不用动的**：
- 登场卡、对话框、存档；
- 脚下墨影（`::before`）；
- 不说话时的虚和退半步（`filter`、`transform` 对图片一样有效）；
- `palette.css` 给 SVG 描线那条（对 `img` 不生效，也不碍事）。

## 二、场景：分层视差 → 整图缓慢推近

### 现在的样子

`CssParallaxRenderer` 往容器里放三层 `div`（天、中、地）：
- 每层一个径向渐变，跟着指针做视差；
- 换场时整层遮住再散开，就是「墨晕开」；
- `--stage-floor` 写死 22%，`--stage-person` 写 1。

### 是加法

`SceneRenderer` 现有的方法（`mount`、`load`、`show`、`beat`、`setInk`、`setDressing`、`resize`、`dispose`）都已经够用：

| 方法 | 整图版怎么做 |
|---|---|
| `load(d)` | **现在是空的，正好用上**：按 `d` 找图、`decode()`。引擎本来就先 `await load` 再 `show`，墨晕开的那一下图已经在内存里，不会先白一下 |
| `show(d)` | 保留现有的遮住—换—散开，中间换的是整图那一层的 `background-image`。有图就藏掉三层渐变、停掉指针视差；没图就和现在一模一样 |
| `beat()` | 现在是一次轻缩放；整图版改成推近快一点 |
| 缓慢推近平移 | 纯 CSS 动画：整图那层 20 秒上下放大约 6%、平移一点，来回。`prefers-reduced-motion` 下停 |
| `setDressing` | 布置是不同的图（公议、夜雨、开课……），见下面的清单 |
| `setInk` | D-082 已经把「墨侵入」改成「饱和度与金的比例随幕数变」。整图上能用 CSS `filter: saturate()` 再叠一层，由幕数推。**效果要 CC3 看图定**，不定就先不做，这个方法本来就是可选的 |

改动量：`CssParallaxRenderer` 加一层、`show`／`load` 各加十来行、一张图表、一段 CSS 动画，大约 80 到 120 行。**不是重写**：三层渐变留着，就是没图时的退路。

**另开一个 `ImageStageRenderer` 也可以**，但得在里面再包一个 CSS 版当退路，才能「这一场有图、下一场没图」，比在 CSS 版里加一层绕。建议加在 CSS 版里。

### 要准备的数据：一张背景表（新文件，比如 `src/scene/backdrops.ts`）

每一条是「地点 · 色板 · 布置 → 图」，另外带几个数：

| 字段 | 为什么要 |
|---|---|
| `floor` | 这张图里人脚踩的那条线离底边多少，写进 `--stage-floor`。3D 版是相机算出来的，整图只能人量一次 |
| `person` | 这张图里人该多大，写进 `--stage-person` |
| `focus` | 推近往哪一点推。人站的地方不能被推出画面 |
| `night` | 夜场的纸色、UI 深浅 |
| `seal`（只有无字碑） | 「无字之碑」结局那枚印叠在哪。印不画进图里，否则八个结局都有印（D-067） |

**数一下剧本里真正用到的组合**：现在的数据里有 **16 种**「地点·色板·布置」；C15 进来后 ch04-18 多一个碑样，是 17 种。D-095 估的是 15 张。**还有一个剧本里没有的维度：昼夜。** 同一个书阁、同一个水墨色板，有的场是白天、有的是夜里（第四章 08、14 场），但场景表里没有「时辰」这一栏。现在是 CSS 版按地点写死夜不夜。要么加一栏，要么接受一个地点只有一个时辰。**这条要 Cowork 定，定了才知道到底要几张背景。**

## 三、新旧并存：PNG 到一张换一张，旧的一张不删

原则：**每一处取图都是「一串候选、第一张存在的就用」，PNG 永远排在候选最前面，SVG／渐变永远在最后。** 删旧的永远不是换新的前提。

1. **立绘**：候选链是 `png:<人>_<装束>` → 换图规则 → 身份变体 → `<人>_<表情>.svg`。
   - B16 刚写的 `spriteCandidates` 已经是这个形状，加一行就行。
   - 没 PNG 的人继续是 SVG，同一屏里可能一个是厚涂一个是剪影。**这个过渡期的样子要不要给玩家看，是 Cowork 的判断**：可以只在 `?art=png` 下混着出，正式网址等一整批验收过再开。
2. **背景**：表里有这一条就用图，没有就画渐变。
3. **验收是入表的门**：图放进仓库不等于上线，**写进清单（立绘清单或背景表）才上线**。清单由人看过截图之后才加那一行，和 D-068「必须有人看截图」是同一道门。
4. **校验器守两件事**：
   - **清单里写了的图，文件必须在**。不在报错，否则那个人会退回 SVG，而没人发现。
   - **旧 SVG 不许在 PNG 清单还没覆盖它时被删**。某个人的 `_default.svg` 没了、清单里又没有他的 PNG，报错。这就是「新的没铺完、旧的已删」的那道闸。
5. **校验器打一张覆盖表**：十四套装束、十七种背景，各自现在是 PNG 还是 SVG／渐变。进度一眼看得出，不靠问。

## 四、另外几件会咬人的事

- **体积。** ChatGPT 落盘测试那张 PNG 是 821 KB。
  - 29 张原图 PNG 大约 25 MB，玩家不该下载原图。
  - 建议入库时转 WebP，立绘高 1536 的透明 WebP 大约两三百 KB，背景类似，总量 6 到 8 MB。
  - 按场景现用现取，`load()` 顺手预取下一场的图。首屏只多第一场的一两张。
  - 转换要一个图片库（比如 sharp），会多一个开发依赖。
- **原图放哪。** 每重生成一次，仓库就多几 MB，而 git 删不掉历史。
  - 建议原图不进仓库，或者进仓库但 `.vercelignore` 挡掉。
  - 进游戏的只有转好的 WebP。
  - 现在 `assets/portraits/` 在仓库根，Vite 不会打包它，用之前要定目录。
- **单文件版（`npm run build:artifact`）装不下图。** 它把 JS 和 CSS 全部内联；二三十张图转 base64 会到十几 MB。建议单文件版继续用 SVG，只有网站版用 PNG。
- **缓存**：Vite 给图加哈希，`vercel.json` 对 `/assets/` 已经是一年缓存，不用改。
- **3D 舞台**：见开头。PNG 背景之后 3D 那条不在玩家主线上。`DEFAULT_RENDERER` 的去留，和 D-086 真机验回退的必要性，要一起重新看。

## 五、工作量与顺序（建议）

| 步 | 谁 | 前提 |
|---|---|---|
| 1 定出图规格：画布、脚线 93%、透明底、WebP | CC3 定，CC1 写入库工具 | 无 |
| 2 立绘候选链 + `<img>` + CSS + 校验两道闸 + 覆盖表 | CC1，一轮 | 1 |
| 3 背景表 + CSS 版加整图层 + 推近 | CC1，一轮 | 1；昼夜那一维要先定 |
