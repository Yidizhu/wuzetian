## 二、怎么验的：`src/scene/stage-preview.html`

留白 ≥ 40%、朱砂 ≤ 3%、「数每个色占的面积」这些指标都是可以量的，眼睛估会往自己想要的方向偏。
所以加了一个只在 dev 下打开的抽查台，直接读画布像素出数：

```bash
npm run dev -- --port 5175
```

- 联排（八场 + 三个色板/幕数变体，每格带数字）：`/src/scene/stage-preview.html`
- 单看一场（活的，带纸纹与墨层）：`/src/scene/stage-preview.html?key=wuzibei&palette=ink&act=1&ink=0`

留白的算法是「画布透明处 + 与底色差值 < 7 的像素」；各色面积用「色板色 × 0.12–1.05 的亮度」做最小二乘拟合归类，
因为 `MeshToonMaterial` 出来的就是「色 × 光照档位」，直接拿最近邻比会把一块暗下去的石青算成焦墨。
第三节表里的每个数字都是这个页面算的，不是我写的。

## 五、顺手修的三件事

1. **金碧板的朱砂其实一直没被收掉。** `palette.css` 里 `:root` 和 `[data-palette="gold"]` 特指度相同，
   金碧那条只是「没有声明 `--c-accent`」，于是 `:root` 的朱砂继续生效——所有 `var(--c-accent, var(--c-ink-4))`
   的回退永远轮不到，D-010 第 1 条「金碧板里没有红」被静静地破了。改成显式 `--c-accent: initial`。
   紫同样处理。规矩和坑都写进了 `palette.md`。
2. **绢纹。** art-style 早就写了「金碧叠绢纹、水墨叠宣纸纹」，代码里两边是同一张噪声。现在金碧场景换成带经纬的细纹。
3. **横屏取景。** 原来的取景只按舞台宽度定视角，横屏的竖向视野会缩掉一半——昭阳殿在桌面上只剩几根柱子顶和一块匾，
   马和屏风全在画外。改成宽、高两个要求各算一次，取大的那个。
