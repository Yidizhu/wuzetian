## markdown 到 JSON 的对照

| 原文写法 | JSON |
|---|---|
| 台词表的「条件」列（在「台词」前后都行），空 = 总是播放 | `Line.when` |
| 场景表 `\| 对诗 \| pd-01 \|` | `Scene.duel`，赢输两条去向把玩家带走 |
| 结果表第四列「她说」，写 `角色key：台词` 或只写台词 | `PoemDuel.onWin/onLose.line` |
| `\| 去向 \| 章末 \|`（D-034 老写法） | `chapterEnd: true` |
| `\| 章末 \| 是 \|` 与「去向」并存（D-039） | `chapterEnd: true` 加 `goto` |
| 选项去向写「章末」（D-043） | 该选项不写 `goto`：结算效果 → 章末结算页 → 场景级去向 |
| 信件表 `\| 截获场景 \| ch02-11 \|`（D-039） | `interceptAt` |
| 信的附页表 `\| 附页 \| 条件 \| 正文 \| 宣读 \|`（D-044） | `body.pages[]`，顺序即表格顺序，条件空 = 总是出现，宣读空 = 是 |
| 场景表 `\| 布置 \| 公议 \|`（D-046） | `dressing: "gongyi"` |

选项去向写「章末」而场景没标章末，会被当场拦下——两处必须一致。

## 三条「不静默丢」的哨兵

- **字段表里认不出的一行**（剧作自查那几行除外，那是明知故不转）。
- **认不出的整张表**。沈衡信的附页表就是这样被抓出来的，后来才有了 D-044。
- **认不出的角色 key**，提示同时写出两条路：新批准的角色要 CC1 加进 `CHARACTER_KEYS`，笔误请 ChatGPT 改。

## 跑法

```bash
node --experimental-strip-types tools/convert-story.ts docs/C-2-第一章前六场.md docs/C-3-第一章后十二场.md docs/C-4-第一章书信.md docs/C0-2-诗词库与对诗.md docs/C-B-结局树.md docs/C-6-第二章大纲.md docs/C-7-第二章前十二场.md docs/C-8-第二章后十二场与书信.md docs/C-9-第三章大纲.md docs/C-10-第三章前十二场.md
npm test && npm run validate && npm run smoke:converted
```

退出码：0 表示没有挡路的问题（「待交付」不算）；1 表示有要改的问题；2 是调用或读写失败。

写盘的三条规矩：问题单末尾 `<!-- 人工补记 -->` 以下不覆盖；输入盖过上一批时 `poems/duels/endings` 按本批重写（正式数据那边一律只合并）；上一批写出过、这一批不再产出的场景与信，文件会删掉。

前向去向：指向还没交的场次时，大纲写明了地点 key 就照它接上并记一条「待交付」；大纲里也没有就停下，不猜 id。
