## 四、铁规矩（改之前先想想为什么有这条）

**流程**
- **D-081**：每一轮，指挥部给每个窗口一条 prompt，写进日志「给各方的当前指令」，旧的标 `← 历史`。
- **D-167**：**每份 prompt 表必须写发送批次**——哪几个同时发、谁等谁。判据只有一个：两个窗口是否碰同一个文件。
- **D-113 写锁**：ChatGPT 改剧本前声明解锁的文件和 sha256，CC2 转换前核"声明时间晚于文件 mtime、仓库里的和声明一致"。
- **D-097**：每份交付文档开头写「默认状态」——哪些当场生效、哪些还要谁来开。
- **R-041 / D-195**：**分配出图前先列磁盘目录和账本**（出过的图别再出一次）；**每上线一张图，同一轮日志必须写出它在剧本的哪一格**（图出了没人接也是错）。CC2 每轮报一次"有图无格"数。

**美术**
- **D-186**：美术不再开新图；要开必须指挥部批。
- **D-200**：**图只生成一次，不退不重出。** 提示词一次写全；CC3 验收只查 C0-3 硬伤（画出了人、可读的字、现代物件）和裁切上线，小毛病记账不退。
- **D-150**：CG 默认竖构图，横的必须记 `focus`。**D-164**：装束跟身份（才人青／受位绯／离宫布衣／才人行装），每张 CG 有「装束」一行。**D-165**：绯不是赭黄，只有满殿无声穿赭黄。

## 六、每一轮怎么转（新窗口照这个做）

```
YIDI 发截图/报告 →
  1. 读文件，不只看截图（"我没截图不代表没有啊，你可以自己去读文件的"）
     — CC1: docs/engine-cc1-bN.md
     — CC2: docs/convert-story.md 末尾那一节
     — CC3: docs/art-cc3-eN.md
     — ChatGPT: docs/CN-*.md
     — Codex: docs/art-gen-ledger.md
  2. 该裁的裁（落成 D-xxx），该记的记（落成 R-xxx）
  3. 写下一轮每个窗口的 prompt，带批次
  4. 把日志写回 docs/00-指挥日志.md，YIDI 发给各窗口
```

**改日志的做法**（很重要，`00-指挥日志.md` 有 67 万字节，别整份重写）：
1. 用 python 脚本做增量：读旧版 → 在 `## 待协调（D-036` 前插新的 R/D 段 → 把所有 `### → ` 开头的旧 prompt 标上 ` ← 历史` → 在 `## 给各方的当前指令\n` 后插新 prompt → 写出新文件。
2. **设备桥有个坑**：`device_commit_files` 会用文件创建时那一刻的内容。所以**每次提交前先 `cp` 到一个全新的文件名**（如 `00-指挥日志-v43b.md`），再 stage、commit，然后 re-stage 核对字节数。
3. 提交前先 stage 一次线上的日志，和自己手里的上一版 `cmp` 一下——CC1 每轮会一并提交日志，可能已经被动过。

**语气**：YIDI 要快，要具体，不要客套。每轮回复结尾必带 prompt 表（批次 / 窗口 / 编号 / 等什么 / 做什么）。裁决要说"为什么"，不要只说"好的"。判错了就在日志里明写是自己判错的（R-050、D-192 都是这么记的）。
