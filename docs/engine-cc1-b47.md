## 一、收诗格式（D-238，给 ChatGPT／CC2）

台词表多一列「收诗」，填 `src/data/poems.json` 的 key：

```
| # | 说话人 | 表情 | 类型 | 条件 | 台词 | 画面 | 收诗 |
|---|---|---|---|---|---|---|---|
| 12 | shenheng | | 说 | | 明月松间照，清泉石上流。 | | wangwei_shanjuqiuming |
```

转出来是那一格上的 `"poem": "<key>"`。**全文在 `docs/story-schema.md` 1.3.2**，含运行语义、校验规矩、JSON 例子。要点：

- **读到那一格就收，不用赢对诗**；对诗赢了照旧收（同一首不会收两次）。
- **条件没满足、整格被跳过**：不收。
- **重复读到**：不收第二次，也不再提示。
- 一格可以同时写「画面」和「收诗」。
- **校验（`npm run validate`）**：key 不在诗库里 → 错误；题记格、事件图格写收诗 → 错误；整列不写（旧稿）→ 正常。

## 二、收诗统计持久化（D-238）

- **病**：「这一章收了哪几首」原来只在内存里一个数组，读档就空了，章末结算页会漏。
- **改**：存档里记**每首诗收在第几章**（`poemChapter`）。章末按章挑出来，读档回来不丢。
- **老档**：以前收过的诗照旧在收藏里；算不出是哪一章收的，就不给它们编一个归属（D-238 明写不编造）。
- **提示**：第一次收到时顶上一行小字「得诗　王维《山居秋暝》」，2.8 秒自己收。
  - 位置在 HUD 那一带下面、正中，**不压底下的对白，也不压画面中间的人和手**（CC3 E42 的要求）；
  - 不收点击，点它就是点画面，剧情照走；
  - 看全图（`data-peek`）和结局卡时不出现。
  - 样式在新文件 `src/styles/poemtoast.css`（CC1 的），CC3 要调改这里。
- **章末空文案**：「这一章没有诗。」→「**本章尚未收录新的诗。**」（R-060）。
- **测试**：读到就收且只提示一次；再读同一首不提示；条件没满足的格不收；收诗归属进存档、老档按空算。
- **浏览器里走过**：临时给 ch01-04「明月松间照。」那一格加标记，读到时顶上出「得诗　王维《山居秋暝》」，存档记下这首诗和「第一章收的」。验完标记已还原（剧本一个字没留）。

## 三、旧信队列提速（D-239）

C54 会把 21 封信的分钟数改短。已经在路上的信按下面这条迁移，**不改分钟数本身、不动场次门、不回退提前投递**：

| 情况 | 怎么办 |
|---|---|
| 时间门已经在计，**记得什么时候开始计的**（B47 起新触发的信都记） | 到期时刻 = 开始时刻 ＋ 新分钟数 |
| 老档，**没记开始时刻** | 最多再等新分钟数：剩得比新分钟数长就缩到新分钟数，短就不动 |
| 分钟数改长了 | **不延长剩余**，照原来的时刻到 |
| 场次门还没过（还要走几场） | 不动，场次门照旧 |
| 已经到案上、已经回过、被截过 | 不动 |

- 迁移在每次投递前跑一遍：开游戏、读档、换场都会过一次，所以后台过了时长、回到前台会补投递。
- 去重照旧（一封信只有一个队列位）；未读上限和截获那条路没动，烟测里截获点照样都截了。
- **测试**：老档长队列缩到新分钟数、剩得短的不动、记了开始时刻的按开始时刻算、场次门没过的不动、已到的不动、改长不延长。
