## 三、换场闪屏（D-211）

### 病在哪

- 原来的换景（`CssParallaxRenderer.show`）是：整层先淡到纸色（180 ms）→ 换背景图 → 再淡回来（300 ms）。**中间那一下台上就是空的**，只剩纸色和上一场的人——这就是「先空一下再出新景」。
- 手机上更明显：背景图是 CSS `background-image`，WebKit 里就算 `decode()` 完了，第一次画也可能晚一帧，空的那一下更长。
- 进场本来就先 `await` 背景和立绘解码（B21），所以不是「图没到就开演」，是换的方式本身会空。

### 改法

- **新景铺在旧景上面一层，透明度 0**。等浏览器画过两帧，新景 420 ms 淡入；盖满之后才拿掉旧景。**旧景从头到尾都在。**
- **旧景交叉期间冻住**：它自己的滤镜（夜、金、墨）和推近到哪儿了，都写成行内的。根上的夜、色调属性这时已经换成新景的，旧景不能跟着变色、跳回原位。
- **有图 → 没图**（那一场确实没有图）：旧景淡出，露出底下的渐变。**两场都是渐变**：照旧墨晕开。
- **「还没到」不等于「没有」**：
  - 进场和预取同时要同一张时只取一次；
  - 一次读不出来再试一次才记成坏图——原来慢网上读失败一次，这一局这个地方就一直是渐变底。
- 读档直接进场的那条路，`show` 自己也先等图，不会先空。

### 验证

浏览器 pane 没有网络限速，改成在页面里把背景图解码**人为拖慢 2.5 秒**（等于 Slow 3G 上图还没下完），读一个停在 ch01-10 最后一格的档、点进 ch01-11，逐帧取样两张背景层的透明度：

- 0—1859 ms：只有掖庭那张，透明度 1（新景还在取，旧景一直在）；
- 1859—2356 ms：两张同时在，诗社那张从 0 淡到 1；
- 2356 ms 起：只剩诗社那张。
